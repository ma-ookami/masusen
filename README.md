# ますせん 公開手順(GitHub Pages + Firebase)

友達がリンクを開いて名前を入れるだけで使えるように、ますせんを公開する手順です。
所要時間は20〜30分くらいです。費用はかかりません(どちらも無料枠で使えます)。

## このフォルダのファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体(画面の骨組み。下の css・js を読み込む) |
| `css/style.css` | 見た目(色・配置・アニメーション) |
| `js/base.js` | 定数・状態・日付・書き込みの土台 |
| `js/data.js` | リアルタイム更新・参加グループ・開催ルールと返事の集計 |
| `js/ui.js` | 返事の保存・シート(下から出る画面) |
| `js/render.js` | 画面の描画 |
| `js/events.js` | 画面遷移・ボタンなどの操作 |
| `js/mascot.js` | ますくん(キャラ) |
| `js/boot.js` | Firebase との接続・新しい版の確認・テーマ・起動 |
| `images/` | 確認用の画像(Git にも公開サイトにも入らない) |
| `tools/stamp.js` | コミットのたびに、index.html の js・css の読み込みに目印(`?v=…`)を付ける。古いファイルが混ざって動かなくなるのを防ぐ |
| `tools/install-hook.js` | 上をコミット前に自動で動かす設定を入れる(別のPCで作業するときに一度だけ `node tools/install-hook.js`) |
| `firebase-config.js` | Firebase の設定(手順4で貼り付ける)と App Check のキー |
| `firestore.rules` | データを守るルール(手順3で貼り付ける) |
| `manifest.webmanifest` | ホーム画面に追加したときのアプリ名・色の設定 |
| `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` | ホーム画面のアイコン |
| `README.md` | この手順書 |
| `OVERVIEW.md` | アプリの概要 |

GitHub にアップロードが必要なのは、`index.html`・`css` フォルダ・`js` フォルダ・`firebase-config.js`・`manifest.webmanifest`・アイコン3つです。`firestore.rules` は Firebase の画面に貼り付けて使います。

---

## 1. Firebase のプロジェクトを作る

1. https://console.firebase.google.com を開き、Google アカウントでログインする
2. 「プロジェクトを作成」(または「プロジェクトを追加」)を押す
3. プロジェクト名に `masusen` などを入れて進む
4. Google アナリティクスは使わないので「オフ」にして、作成する

## 2. 匿名ログインをオンにする

友達がログイン操作をしなくても、ブラウザごとに見分けられるようにする設定です。

1. 左のメニューの「構築」→「Authentication」→「始める」
2. 「Sign-in method」(ログイン方法)タブを開く
3. 一覧から「匿名」を選び、「有効にする」をオンにして保存する

## 3. データベースを作ってルールを貼る

1. 左のメニューの「構築」→「Firestore Database」→「データベースを作成」
2. ロケーションは `asia-northeast1 (Tokyo)` を選ぶ(あとから変えられません)
3. 「本番環境モードで開始」を選んで作成する
4. 作成できたら「ルール」タブを開く
5. 最初から入っている文字をすべて消し、このフォルダの `firestore.rules` の中身をすべてコピーして貼り付ける
6. 「公開」を押す

## 4. 設定をコピーする

1. 左上の歯車マーク →「プロジェクトの設定」
2. 下のほうの「マイアプリ」で、ウェブのマーク `</>` を押す
3. アプリのニックネームに `masusen` などを入れて「アプリを登録」
   (「Firebase Hosting も設定する」のチェックは不要です)
4. 表示されたコードのうち、`const firebaseConfig = { ... };` の `{ }` の中身をコピーする
5. このフォルダの `firebase-config.js` を開き、`window.FIREBASE_CONFIG = { ... };` の `{ }` の中身を、コピーしたものに置き換えて保存する

置き換えたあとは、たとえば次のようになります(値は人によって違います)。

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIzaSy...",
  authDomain: "masusen-xxxx.firebaseapp.com",
  projectId: "masusen-xxxx",
  storageBucket: "masusen-xxxx.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef"
};
```

> この値は公開されても問題ありません。データは手順3のルールで守られています。

## 5. GitHub で公開する

1. https://github.com にログインする(アカウントがなければ作る)
2. 右上の「+」→「New repository」
3. Repository name に `masusen` と入れ、**Public** を選んで「Create repository」
4. 「uploading an existing file」のリンクを押す
5. `index.html`・`css` フォルダ・`js` フォルダと `firebase-config.js` をドラッグして置き、下の「Commit changes」を押す
6. リポジトリの「Settings」→ 左の「Pages」
7. 「Branch」で `main` と `/ (root)` を選び「Save」
8. 1〜2分待つと、上に公開URLが出ます
   `https://(あなたのユーザー名).github.io/masusen/`

## 6. 公開URLを Firebase に登録する

1. Firebase の「Authentication」→「設定」タブ →「承認済みドメイン」
2. 「ドメインの追加」で `(あなたのユーザー名).github.io` を追加する

## 7. 動作確認

1. 公開URLを開き、グループを作る
2. 共有ボタン(📋)から招待リンクをコピーする
3. スマホや、パソコンのシークレットウィンドウでそのリンクを開き、別の名前で参加する
4. 片方で「ます」を押すと、もう片方にすぐ反映されれば完成です

---

## うまくいかないとき

| 表示 | よくある原因 |
|---|---|
| 「Firebaseの設定が読み込めませんでした」 | `firebase-config.js` を貼り付けていない、またはアップロードし忘れている |
| 「サーバーにつながりませんでした」 | 手順2の「匿名」がオンになっていない |
| 「データを読み込めませんでした」 | 手順3のデータベース作成、またはルールの「公開」がまだ |
| 「保存できませんでした」 | ルールの貼り付けが途中で切れている。`firestore.rules` を丸ごと貼り直す |
| ページが404になる | 手順5の Pages 設定後、数分待っていない。URLの最後の `/masusen/` を確認 |

## App Check を設定する(無料枠を荒らされないように)

本物のアプリ(公開ページ)以外からのアクセスを Firebase が弾くようになります。利用者の操作は増えません。
reCAPTCHA Enterprise(Google Cloud Fraud Defense)を使います。Google Cloud で支払い情報を登録しなければ、無料の Essentials プラン(月1万回まで)が自動で使われ、請求は発生しません。

1. **reCAPTCHA のキーを作る(Google Cloud コンソール)**
   - https://console.cloud.google.com/security/recaptcha?project=masusen-30328 を開く
   - 「API を有効にする」が出たら押す
   - 「キーを作成」→ 表示名:`masusen`、アプリケーションの種類:**ウェブ**
   - ドメインに `(ユーザー名).github.io` と `localhost` を追加して作成
   - 作成されたキーの **ID(サイトキー、`6L…` で始まる文字列)** を控える
2. **Firebase で App Check をオンにする**
   - Firebase コンソールの「App Check」→「アプリ」タブ → ウェブアプリ `masusen`
   - 「**reCAPTCHA Enterprise**」を選び、手順1の**サイトキー**を貼る
   - 「トークンの有効期間」は **1日** にしておくと、無料枠をほとんど使いません
   - 保存
3. **アプリにサイトキーを入れる**
   - `firebase-config.js` の `window.APPCHECK_SITE_KEY = "";` の `""` の中に**サイトキー**を貼る
   - `index.html`・`css`・`js` と `firebase-config.js` を GitHub にアップロードする
4. **1日ほど使ってから「適用」する**
   - App Check の「API」タブ →「Cloud Firestore」で、「確認済みのリクエスト」が増えていることを確認する
   - 確認できたら「適用」を押す(「Authentication」も同じように適用できます)
   - **アップロード前に適用すると、アプリが動かなくなります。** 必ず3の後に行ってください
   - 適用後、古い画面を開きっぱなしの人は、アプリの「↻ 更新」を押してもらってください

## ホーム画面に追加する(アプリのように使う)

GitHub には次のファイルもアップロードしておいてください(`index.html` と同じ場所に置きます)。

- `manifest.webmanifest`
- `icon-192.png`
- `icon-512.png`
- `apple-touch-icon.png`

**iPhone(Safari)**
1. Safari でアプリを開き、自分のグループを表示する
2. 下の共有ボタン(□に↑)→「ホーム画面に追加」
3. 名前が「ますせん」になっていることを確認して「追加」

**Android(Chrome)**
1. Chrome でアプリを開く
2. 右上の「︙」→「ホーム画面に追加」(または「アプリをインストール」)

**ホーム画面から開いたときの注意**
- iPhone では、ホーム画面のアプリは Safari とは別のブラウザ扱いになります。最初の1回だけ参加画面が出るので、「前に参加したことがある人」から自分の名前を選んでください。
- グループの一覧が空のときは、トップ画面の「招待リンクで参加」に招待リンクを貼り付けると開けます。
- 2回目からは、最後に開いたグループが自動で開きます。

## アプリを更新するとき(VS Code)

1. 手元で確認する:`masusen` フォルダで `npx http-server -p 8080 -c-1` を動かし、http://localhost:8080 を開く
   (App Check を「適用」したあとは、Firebase の App Check に localhost 用の「デバッグトークン」の登録が必要です)
2. VS Code の「ソース管理」でメッセージを書いて「コミット」→「変更の同期」
3. 1〜2分で公開サイトに反映されます
4. `firestore.rules` を変えたときは、Firebase の「Firestore Database」→「ルール」に貼り直して「公開」も必要です

## 知っておくこと

- **リンクを知っている人は誰でも参加できます。** グループのIDはランダムで推測されにくいですが、リンクはグループの中だけで共有してください。
- **別のスマホやブラウザ(LINEの中のブラウザなど)で開くと、参加画面が出ます。** ブラウザごとに見分けているためです。「前に参加したことがある人」から自分の名前をタップすれば、同じ人として前の返事を引き継げます。名前を入れ直すと別の人として増えてしまうので注意してください。
- **合言葉(数字4桁)**:グループを作る人は必須、ほかのメンバーは任意です。設定した人として別の端末から入るときに必要になり、なりすましを防げます。忘れたときは、最初に参加した端末の ⚙ 設定で変更できます。
- **グループの管理(メンバーを外す・削除)**:グループを作った端末か、作った人として合言葉で入り直した端末でできます。合言葉を変えても、確認済みの端末は管理できたままです。リセットしたいときは、作った端末で合言葉を設定し直してください。
- **同じ人が2人になってしまったら**、管理できる端末の ⚙ 設定 →「管理」タブから片方を外せます。
- **グループを抜ける**:⚙ 設定 →「その他」タブから。自分の名前と返事が消えます(作った人は抜けられません)。
- **グループを作れるのは、1つのブラウザで3つまでです。** 使わなくなったグループを削除すると、また作れます。
- **名前は本名ではなくニックネームがおすすめです**(10文字まで)。招待リンクを知っている人は、メンバーの名前を見られます。スクショを共有するときは「匿名表示」を使ってください。
- **claude.ai 版のデータは引き継がれません。**
